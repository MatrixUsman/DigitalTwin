The code supplies concrete reasons not to run its default workflow unchanged:

- [`utils/evaluate_utils.py`](https://github.com/zamanzadeh/CARLA/blob/600d4f2af3e625e63e0204617f8b29d227ca2973/utils/evaluate_utils.py) computes `precision_recall_curve(labels, scores)` and returns maximum F1. [`carla_classification.py`](https://github.com/zamanzadeh/CARLA/blob/600d4f2af3e625e63e0204617f8b29d227ca2973/carla_classification.py) evaluates this every epoch and saves the checkpoint when it improves. [`common_config.py`](https://github.com/zamanzadeh/CARLA/blob/600d4f2af3e625e63e0204617f8b29d227ca2973/utils/common_config.py) maps SWaT/WADI's so-called validation loader to `train=False`. **Inference from this call chain:** test labels guide both threshold scoring and checkpoint selection.
- [`data/SWAT.py`](https://github.com/zamanzadeh/CARLA/blob/600d4f2af3e625e63e0204617f8b29d227ca2973/data/SWAT.py) expects derived `<name>_train.csv` / `<name>_test.csv`, an `attack` label, and 51 positional channels. It fills NaNs with zero, uses window 200 / stride 10, and labels a window positive if any included label is positive. Training minima/maxima are saved for test min–max transformation; training-path transformation must be traced through wrappers before claiming consistent scaling.
- [`data/WADI.py`](https://github.com/zamanzadeh/CARLA/blob/600d4f2af3e625e63e0204617f8b29d227ca2973/data/WADI.py) expects `<name>_14days_new.csv` and `<name>_attackdataLABLE.csv`, slices columns `3:123` (120 channels), zero-fills NaNs, and uses training mean/std for test standardization. Windows contain **400 sampled observations over 2,000 raw rows**, sampling every fifth row and advancing starts by 10 rows. Positive labels use any sampled attack. These choices differ from the paper's general 200-window/123-channel description; provenance and timestamp mapping require resolution.
- [`requirements.txt`](https://github.com/zamanzadeh/CARLA/blob/600d4f2af3e625e63e0204617f8b29d227ca2973/requirements.txt) pins a mixed older stack, including torch 1.13.0 and NumPy 1.22.4 alongside pandas 2.2.2 and SciPy 1.13.1. Compatibility was not tested. Do not silently replace dependencies or claim an unmodified runnable artifact.

A future run can preserve the architecture while selecting checkpoints using training/benign validation only and locking the anomaly rule before test evaluation. Use native majority-class decisions or a preregistered benign-calibration rule, then evaluate one score per causally aligned timestamp. Any departure from author window labels, splits, checkpoint selection or thresholding must be recorded as **adapted evaluation**, not an exact reproduction of published numbers. Synthetic negatives in this method are training augmentation, not real attacks or benchmark results.

This artifact is useful for checking dataset-version discipline and a simple CNN detector reference. A chronological, purged split and training-only scaling would be a declared protocol change. Its SWaT README's introductory feature/attack counts also conflict with the general repository description; do not propagate those counts without inspecting raw files and processing code.

## Recommendation from this audit

Do **not** start with DPDGAD or unmodified CARLA. DPDGAD lacks verifiable full protocol and usable code; CARLA has explicit test-guided checkpoint/threshold choices and paper/code discrepancies. Prefer a candidate from the wider audit with accessible author code and both datasets, conditioned on a test-independent evaluation wrapper. If none clears that gate, first validate the shared loader/split/metric pipeline with a small fixed statistical or forecasting control, labelled as our own control rather than a faithful recent-paper reproduction. The NDSS CNN is a documented reference for that control, with the environment and split caveats above. No baseline result is claimed here.
