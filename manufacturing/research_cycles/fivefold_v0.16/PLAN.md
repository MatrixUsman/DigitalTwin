# Five-fold temporal validation of the proposed reference

## Material Passport
Project: manufacturing. Operator: Codex. Requested manuscript author: Muhammad Usman. Date: 18 October 2026. Scope: user-requested five-fold cross-validation, implemented as expanding-window normal-prediction validation. This is a retrospective developmental diagnostic on existing synthetic commissioning episodes, not new attack confirmation or independent robots.

Use exactly the nine `train_Q{1,2,3}_{0,1,2}.npz` episodes in `local/recovery_v0.8/runs/confirmation_002`, with only `measurements`, `available` and `valid` members. Each has 1,200 observations. No calibration, development, attack or new public test file is read. Preserve raw and old fitted artifacts.

For each episode define six consecutive blocks of 200 observations. In fold k=1,...,5, fit on [0,200k), initialize the validation reference on [200k,200k+100), and score [200k+100,200(k+1)). Split before constructing history; no window crosses a split or an episode. Corresponding prefixes from the three episodes of one plant jointly fit that plant. Each fold has 300 scored observations per plant, 900 total. The validation prefix is known-normal state initialization, not fitted-model training. It is excluded from all reported errors.

Refit every mean, scale, ARX coefficient, RBF center/width and correction weight within each fold. Use existing fixed per-plant settings: ARX orders 8/16/32, ridge 1e-7; 32 RBF centers; Q1 width 1/ridge .01, Q2 width .5/ridge .001, Q3 width 1/ridge .001. These settings were chosen in earlier development; this is not nested cross-validation or an unbiased reassessment of their original selection. No model selection, threshold calibration, alarm evaluation or attack-label access occurs. Both methods share the same freshly fitted ARX and eligible targets. Warmup=100, command lags=1,4,16,32.

Reject unstable ARX recurrences, nonfinite output or invalid input. Preserve failed plant-fold outcomes with zero coverage; do not silently replace them or change settings. Report all 15 plant-fold outcomes, all five folds, target coverage, standardized RMSE and native per-channel RMSE. Summaries across overlapping folds are descriptive; do not infer confidence intervals, p-values or five independent acquisitions. Native units are radians and radians/s. A shorter validation horizon also limits comparison with prior 1,100-target episodes.

Bound one sequential run to 120 s wall, 90 s CPU, 1 GiB sampled RSS and 50 MiB output. The earlier 30-fit correction pilot took 16.115 s wall; this smaller diagnostic has 15 ARX fits plus 15 corrections and no simulation generation. Validate split isolation, future-mutation invariance, fitting determinism, score alignment, failure reporting and serialization with synthetic fixtures first. Freeze source/input hashes, split manifest, configuration, dependencies and test receipt before execution. Save all fitted models, aligned scores, resource receipts and failures. Verify saved score arithmetic after execution; keep former evidence seals unchanged.

Temporal splitting rationale: https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html . The explicit splitter here requires no scikit-learn dependency. The project rules and explicit user request authorize implementing the bounded study; optional skill command-confirmation prompts do not supersede that authorization.
