## Recommendation and its limits

**Prioritize industrial robotic-arm monitoring, starting with the original CASPER pick-and-place collection.** It is a concrete manufacturing setting distinct from water infrastructure, and it connects a recent physical-anomaly detector to a recent explicit digital-twin framework. Open-data access checks are documented separately from actual receipt in the [dataset screen](literature/OPEN_DATASET_SCREEN_2026-10-16.md).

The recommended critical-learning set is **CASPER (2024), TWINE (2026), and CatBoost on CASPER (2026)**. All three now have matched author repositories associated with original CASPER filenames. **We have not verified three published experiments using one byte-identical release under comparable information access.** CatBoost's source has serious label/preprocessing problems and remains on hold for numerical comparison. This is a useful three-paper study set, not a finalized “best three” experimental set.

The earlier broad phase/sequence question remains provisional. A defensible near-term scope is detecting documented robotic-motion deviations under explicit sensor and controller trust assumptions. These data do not by themselves establish malicious intent, complete cyberattack campaigns, or discrimination between every fault and attack. No new title, architecture or novelty claim is finalized.

Even the confirmed collection overlap does **not** establish fair inputs: CASPER's external IMU defense and TWINE's controller-telemetry classifier observe different information. The former emphasizes independence from compromised controller/network values. Comparing their headline scores would confound input trust, supervision and evaluation. A future experiment must either define separate information-access tracks or explicitly adapt methods to common permitted inputs, with the resulting runs labelled modified-protocol evaluations. CatBoost's synthetic outlier labels cannot be treated as recorded cyberattack ground truth.

The original provider currently identifies **version 3, 2023-02-11, CC BY-SA 4.0**. An unauthenticated archive request returned HTTP 200 and ZIP headers for **2,824,019,108 bytes** (about 2.82 GB compressed; provider file total about 7.90 GB). The response body was not read. No institutional approval was required in that check. This verifies a public download route, not archive integrity, receipt or a stable future endpoint. The newer listing has different license metadata; do not transfer it to original files.

The stronger open alternatives make manufacturing feasible to investigate while water access is pending. They do not demonstrate that any particular novelty or three-paper comparison is already feasible.

## Closest prior work and scope guardrails

The author's [CASPER+ research programme](https://iotgarage.net/projects/CASPERPlus) already describes task segmentation, cold-start monitoring, IMU-to-robot-state estimation and cross-modal spoofing detection. This is a public research-programme description, not a verified additional published baseline or results paper. It is nevertheless a reason to avoid claiming that these general directions are unexplored.

TWINE's inspected implementation stores observed properties and classifier outputs in an Azure twin. It does not establish a physics-based predictive residual model. If our later contribution uses one, we must define and validate its state/model/synchronization and test the contribution against suitable controls. “ISO 23247-compliant” is the paper's claim, not an independent certification from this audit.

Keep older manufacturing twin work, frameworks without executable detection evaluation, and recent fault-only studies in the [background register](LITERATURE_EVIDENCE.md), not in the three baseline count. Journal prestige, fashionable titles and very high published scores cannot override the admission rules.

## Search coverage and limitations

Parallel searches covered explicit manufacturing twins, shared-dataset detectors and open provider data. Sources included publisher/DOI records, institutional/author manuscripts, GitHub author trees and Kaggle/Zenodo/CMU metadata. Each detailed screen records its own queries and retrieval limits. Additional synthesis queries included `"TWINE" "ISO 23247" github dataset`, `"industrial-robotic-arm-anomaly-detection" paper`, `"CASPER dataset" anomaly detection`, and `"right_arm.csv" anomaly detection paper`. Publisher records and matched author code, not search-result summaries, support admissions.

The search established a plausible three-paper learning set with author-code links, but did not establish an execution-ready shared-protocol trio. This is a statement about the evidence obtained, not proof that no better set exists. No author was contacted. Full manuscript access gaps, unknown code licenses, release ambiguity, unequal supervision and label/protocol defects remain explicit blockers.
